## Реалистичная задача

Команда поддержки хочет понять, какие combinations команды и канала требуют
дополнительного внимания. У каждой команды свой SLA target. Нужно сравнить
долю превышений SLA и типичное время решения закрытых обращений, проверить
June/July change и передать воспроизводимый notebook.

Dataset синтетический. Пороги SLA заданы в справочнике и не являются
универсальной отраслевой нормой.

## Создай локальные источники

Запусти bootstrap cell один раз в отдельном notebook или script. Fixed seed
создаёт одинаковые файлы у всех learners.

```python
from pathlib import Path

import numpy as np
import pandas as pd

rng = np.random.default_rng(20260727)
data_dir = Path("data")
data_dir.mkdir(exist_ok=True)

request_count = 48
request_number = np.arange(request_count)
created = pd.Series(
    pd.date_range(
        "2026-06-01 09:00",
        periods=request_count,
        freq="30h",
    )
)
duration_hours = rng.integers(2, 31, size=request_count).astype(float)
is_open = request_number % 7 == 0

closed = created + pd.to_timedelta(duration_hours, unit="h")
closed.loc[is_open] = pd.NaT

team_id = np.resize(
    np.array(["T1", "T2", "T3", "T4"]),
    request_count,
).copy()
channel = np.resize(
    np.array(["chat", "email", "phone"]),
    request_count,
)
priority = np.resize(
    np.array(["low", "medium", "high"]),
    request_count,
)
status = np.where(is_open, "open", "closed")
satisfaction = rng.integers(1, 6, size=request_count).astype(float)
satisfaction[is_open] = np.nan
satisfaction[8] = np.nan

requests_source = pd.DataFrame(
    {
        "request_id": [f"R-{value:03d}" for value in request_number + 1],
        "created_at": created.dt.strftime("%Y-%m-%d %H:%M"),
        "closed_at": closed.dt.strftime("%Y-%m-%d %H:%M"),
        "team_id": team_id,
        "channel": channel,
        "priority": priority,
        "status": status,
        "satisfaction": satisfaction,
    }
)

requests_source.loc[10, "created_at"] = "bad-date"
requests_source.loc[15, "closed_at"] = "2026-06-01 00:00"
requests_source.loc[20, "team_id"] = "T9"
requests_source = pd.concat(
    [requests_source, requests_source.iloc[[5]]],
    ignore_index=True,
)

teams_source = pd.DataFrame(
    {
        "team_id": ["T1", "T2", "T3", "T4"],
        "team_name": ["Atlas", "Boreal", "Cedar", "Delta"],
        "region": ["north", "south", "east", "west"],
        "sla_hours": [8.0, 12.0, 24.0, 16.0],
    }
)

requests_source.to_csv(data_dir / "requests.csv", index=False)
teams_source.to_excel(data_dir / "teams.xlsx", index=False)
```

После bootstrap начни новый analysis notebook с чтения файлов. Не используй
`requests_source` или `teams_source` как вход анализа.

## Data contract

`requests.csv`:

| Column | Смысл |
| --- | --- |
| `request_id` | идентификатор обращения; ожидается unique на grain обращения |
| `created_at` | время создания |
| `closed_at` | время закрытия; допустимо отсутствует у `open` |
| `team_id` | ключ команды |
| `channel` | chat, email или phone |
| `priority` | low, medium или high |
| `status` | open или closed |
| `satisfaction` | оценка 1–5; может отсутствовать |

`teams.xlsx`:

| Column | Смысл |
| --- | --- |
| `team_id` | unique key команды |
| `team_name` | отображаемое имя |
| `region` | регион команды |
| `sla_hours` | target maximum для duration закрытого обращения |

Grain `requests` — одно обращение. Grain `teams` — одна команда. Ожидаемая
cardinality merge — many-to-one.

## Required scope

1. Восстановить exact environment через `uv sync --locked`.
2. Загрузить CSV/XLSX с явными identifier dtypes.
3. Зафиксировать shape, types, пропуски, exact duplicates, key uniqueness и
   категории.
4. Разобрать timestamps, рассчитать resolution hours и изолировать
   противоречивые строки.
5. Разделить quality issues и обращения вне scope closed-analysis.
6. Выполнить left many-to-one merge со справочником, измерить unmatched keys.
7. Рассчитать `sla_breached` через NumPy comparison двух equal-shape arrays.
8. Создать summary минимум на grain `month × team × channel`: unique requests,
   breach rate и median resolution hours.
9. Создать pivot или другую exact evidence table для comparison.
10. Построить минимум два charts для разных вопросов:
    - comparison team/channel;
    - June/July change.
11. Сформулировать минимум три findings, limitations и следующий вопрос.
12. Выполнить Restart Kernel and Run All, сохранить notebook и `uv.lock`.
