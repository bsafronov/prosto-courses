Таблица редко сообщает, какая строка ошибочна. Она показывает симптомы:
повтор, пустое значение, дата в неожиданном формате или число за допустимой
границей. Если сразу вызвать `dropna()` или `drop_duplicates()`, таблица станет
аккуратнее, но ты потеряешь ответ на главный вопрос: **что изменилось и почему
этому результату можно доверять?**

В этом уроке ты подготовишь данные для вопроса:

> Какова выручка оплаченных заказов по дням?

Сначала предскажи: достаточно ли удалить все строки с пустыми значениями?
Сохрани ответ — вернёмся к нему после диагностики.

## Очистка — это проверяемое решение

Полезная модель состоит из четырёх частей:

1. **Исходник** остаётся неизменным.
2. **Симптом** измеряется до исправления.
3. **Правило** связывает действие с аналитическим вопросом.
4. **Контроль** показывает, какие строки и показатели изменились.

<Callout kind="key">
  Чистые данные — не таблица без пустых ячеек. Это данные, пригодные для
  конкретного вопроса, с объяснимой историей изменений.
</Callout>

Например, пустая длительность доставки может быть ошибкой у завершённой
доставки и нормальным состоянием у незавершённой. Один симптом приводит к
разным решениям в зависимости от смысла строки.

| Наблюдение | Что проверить | Возможное действие | Контроль |
| --- | --- | --- | --- |
| Две полностью одинаковые строки | Это повтор одной записи или допустимые события? | Удалить доказанный точный повтор | Число удалённых строк |
| Одинаковый идентификатор | Идентификатор строки, заказа или клиента? | Не удалять до проверки grain | Уникальность на заявленном уровне |
| Дата не разбирается | Опечатка, другой формат или отсутствующее значение? | Преобразовать в `NaT` и изолировать | Число неразобранных дат |
| Пустое число | Можно ли восстановить его из другого поля? | Изолировать или обоснованно восстановить | Число затронутых строк |
| Отменённый заказ | Входит ли он в аналитический вопрос? | Исключить из расчёта, не называя ошибкой | Число строк вне scope |

`grain` — что представляет одна строка. В таблице заказов это может быть заказ,
а в таблице позиций — одна позиция заказа. Пока grain не назван, одинаковый
`order_id` ещё не доказывает дубль.

## Создай локальный исходник

Запусти bootstrap cell один раз. Она создаст синтетический CSV рядом с
notebook. Значения намеренно содержат разные симптомы качества.

```python
import pandas as pd

orders_source = pd.DataFrame(
    {
        "order_id": [1001, 1002, 1002, 1003, 1004, 1005],
        "order_date": [
            "2026-07-01",
            "2026-07-02",
            "2026-07-02",
            "31/02/2026",
            "2026-07-04",
            "2026-07-05",
        ],
        "units": [2, 1, 1, 3, None, 0],
        "unit_price": [500, 1200, 1200, 450, 800, 1000],
        "status": ["paid", "paid", "paid", "paid", "paid", "cancelled"],
    }
)

orders_source.to_csv("orders_raw.csv", index=False)
```

Начни analysis cell с чтения файла, а не с объекта `orders_source`. Так
notebook воспроизводит реальную границу «файл → анализ».

```python
raw = pd.read_csv("orders_raw.csv")
raw
```

Не изменяй `raw`. Новая стадия получает новое имя:

```python
working = raw.copy()
```

Это не требование создавать копию после каждой строки кода. Здесь отдельное имя
помогает сохранить исходное evidence и сравнивать стадии.

## Зафиксируй baseline

До исправлений измерь то, что можешь наблюдать без догадок:

```python
baseline = pd.Series(
    {
        "rows_raw": len(raw),
        "exact_duplicate_rows": int(raw.duplicated().sum()),
        "missing_units": int(raw["units"].isna().sum()),
        "unique_order_ids": raw["order_id"].nunique(),
    },
    name="value",
)

baseline
```

Ожидаемый baseline:

| Показатель | Значение |
| --- | ---: |
| Строк в исходнике | 6 |
| Полностью одинаковых повторных строк | 1 |
| Пропусков в `units` | 1 |
| Уникальных `order_id` | 5 |

Разница между шестью строками и пятью идентификаторами указывает на повтор, но
не объясняет его. В этом примере две строки совпадают по всем столбцам, поэтому
можно удалить именно точный повтор. Метод
[`DataFrame.drop_duplicates`](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.drop_duplicates.html)
по умолчанию сравнивает все столбцы.

<Callout kind="warning">
  `drop_duplicates(subset=["customer_id"])` не означает «убрать дубли». Такая
  команда оставит только один заказ каждого клиента и удалит допустимые
  повторные покупки. Сначала назови grain и правило уникальности.
</Callout>

## Преобразуй ошибку в наблюдаемый сигнал

Удали доказанный точный повтор, затем разбери даты и числа:

```python
working = raw.drop_duplicates().copy()

working = working.assign(
    order_date=lambda frame: pd.to_datetime(
        frame["order_date"],
        errors="coerce",
    ),
    units=lambda frame: pd.to_numeric(
        frame["units"],
        errors="coerce",
    ),
)
```

Аргумент `errors="coerce"` у
[`pandas.to_datetime`](https://pandas.pydata.org/docs/reference/api/pandas.to_datetime.html)
заменяет неразбираемую дату на `NaT`. Это не исправление даты: это способ
сделать проблему доступной для фильтра и подсчёта. То же правило действует для
неразбираемого числа, превращённого в пропуск.

Покажи строки, требующие отдельного решения:

```python
quality_issues = working.loc[
    working["order_date"].isna() | working["units"].isna(),
    ["order_id", "order_date", "units", "unit_price", "status"],
]

quality_issues
```

Официальное руководство pandas отдельно описывает представление и обнаружение
[missing data](https://pandas.pydata.org/docs/user_guide/missing_data.html).
Но метод не решает, допустим ли пропуск в твоём контексте. Это определяет
аналитический вопрос.

Для выручки оплаченных заказов нужны разобранная дата, положительное количество
и статус `paid`. Отменённый заказ исключается по scope вопроса, а не потому,
что строка «грязная».

```python
ready = working.loc[
    working["status"].eq("paid")
    & working["order_date"].notna()
    & working["units"].notna()
    & working["units"].gt(0)
].copy()

ready["revenue"] = ready["units"] * ready["unit_price"]
```

Мы не заполняем неизвестное `units` средним значением. Такое заполнение
придумало бы выручку, которой нет в исходнике. Строка остаётся в `working` и
попадает в `quality_issues`, где её можно исправить после сверки с источником.

## Докажи результат контролями

Собери контрольные показатели в одном месте:

```python
controls = pd.Series(
    {
        "rows_raw": len(raw),
        "exact_duplicates_removed": len(raw) - len(working),
        "rows_ready": len(ready),
        "unique_ready_orders": ready["order_id"].nunique(),
        "ready_revenue": ready["revenue"].sum(),
    },
    name="value",
)

controls
```

Ожидаемый результат:

| Показатель | Значение |
| --- | ---: |
| Строк в исходнике | 6 |
| Удалено точных повторов | 1 |
| Строк готово к расчёту | 2 |
| Уникальных заказов в расчёте | 2 |
| Выручка готовых строк | 2 200 |

Добавь проверки, которые должны остановить notebook при нарушении контракта:

```python
assert len(raw) == 6
assert len(raw) - len(working) == 1
assert ready["order_id"].is_unique
assert ready["order_date"].notna().all()
assert ready["units"].gt(0).all()
assert ready["revenue"].sum() == 2200
```

Если следующая выгрузка неожиданно размножит идентификатор или изменит итог,
`assert` покажет место нарушения раньше, чем ошибочный вывод попадёт в график.

## Необязательное углубление

<Callout kind="advanced">
  Если есть ещё пять минут, собери проверки в небольшую функцию
  `validate_ready(frame)`. Пусть она ничего не исправляет, а только проверяет
  grain, обязательные значения и допустимые границы через `assert`. Запусти её
  для `ready`, затем намеренно добавь повтор и убедись, что проверка падает с
  понятным сообщением.
</Callout>

## Что перенести в следующий анализ

Вернись к первоначальному прогнозу. Удаление всех строк с пустыми значениями не
подходит: оно смешивает ошибку завершённой доставки с нормальным состоянием
незавершённой и скрывает масштаб изменений.

Рабочая последовательность:

1. сохрани `raw`;
2. измерь baseline;
3. назови grain и аналитический вопрос;
4. свяжи каждый симптом с правилом;
5. изолируй спорные строки вместо догадки;
6. сравни контроли;
7. выполни Restart and Run All.
