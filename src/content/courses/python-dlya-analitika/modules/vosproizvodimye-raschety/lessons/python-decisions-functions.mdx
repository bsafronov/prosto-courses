Аналитический расчёт часто содержит правило: учитывать только оплаченные
заказы, отдельно обрабатывать нулевую базу или повторять одну проверку для
нескольких наблюдений. Для этого не нужна сложная архитектура. Достаточно
понять три конструкции: `if`, `for` и функцию с `return`.

## Условие выбирает ветку

```python
status = "cancelled"

if status == "paid":
    included = True
else:
    included = False
```

Выражение `status == "paid"` возвращает `bool`. Двоеточие открывает ветку, а
отступ показывает, какие строки ей принадлежат.

Операторы сравнения:

- `==` — равно;
- `!=` — не равно;
- `>` и `<` — больше и меньше;
- `>=` и `<=` — сравнение с включённой границей.

`=` присваивает значение, а `==` сравнивает. Эта разница особенно заметна в
условиях.

## Функция называет повторяемое правило

```python
def net_revenue(order):
    if order["status"] != "paid":
        return 0.0

    gross = order["units"] * order["unit_price"]
    return gross * (1 - order["discount_rate"])
```

Функция получает `order` и явно возвращает результат. Вызов:

```python
first_order = {
    "units": 2,
    "unit_price": 500.0,
    "discount_rate": 0.1,
    "status": "paid",
}

net_revenue(first_order)
```

Результат — `900.0`.

<Callout kind="key">
  Хорошая маленькая функция отвечает на один вопрос и возвращает результат.
  Она не должна зависеть от переменной, случайно оставшейся в другой notebook
  cell.
</Callout>

Если забыть `return`, Python вернёт `None`. Напечатанное внутри функции число
не становится её результатом:

```python
def broken_revenue(order):
    value = order["units"] * order["unit_price"]
    print(value)
```

## Цикл повторяет действие

```python
orders = [
    {
        "units": 2,
        "unit_price": 500.0,
        "discount_rate": 0.1,
        "status": "paid",
    },
    {
        "units": 1,
        "unit_price": 1200.0,
        "discount_rate": 0.0,
        "status": "cancelled",
    },
    {
        "units": 3,
        "unit_price": 450.0,
        "discount_rate": 0.0,
        "status": "paid",
    },
]

revenues = []

for order in orders:
    revenues.append(net_revenue(order))

total_revenue = sum(revenues)
```

`revenues` станет `[900.0, 0.0, 1350.0]`, а итог — `2250.0`.

Цикл полезен для понимания повторения и для задач, где каждый шаг действительно
имеет отдельное действие. Но аналитические вычисления по большим наборам не
нужно автоматически писать как `for row in rows`. NumPy и pandas выражают
массовую операцию короче и обычно эффективнее.

## Порядок ячеек — часть результата

Notebook должен сначала определить `net_revenue`, затем создать `orders`, затем
вызвать функцию. Если вызов расположен выше определения, текущий kernel может
скрыть ошибку, потому что функция осталась в памяти после старого запуска.
Restart + Run All обнаружит такую зависимость.
