Вопрос «какова выручка оплаченных заказов за июль?» уже содержит три решения:

- measure — выручка;
- population — оплаченные заказы;
- period — июль.

Если сначала вызвать методы pandas, а потом придумывать смысл получившейся
таблицы, легко включить отмены или не тот период. Начинай с проверяемого
условия.

## Создай проверенные исходные строки

```python
import pandas as pd

raw = pd.DataFrame(
    {
        "order_id": ["A-1", "A-2", "A-3", "A-4", "A-5", "A-6"],
        "order_date": [
            "2026-06-30",
            "2026-07-01",
            "2026-07-10",
            "2026-07-15",
            "2026-07-31",
            "2026-08-01",
        ],
        "region": ["north", "north", "south", "south", "north", "south"],
        "units": [2, 1, 3, 1, 4, 2],
        "unit_price": [500.0, 1200.0, 450.0, 800.0, 600.0, 700.0],
        "discount_rate": [0.0, 0.1, 0.0, 0.0, 0.2, 0.0],
        "status": ["paid", "paid", "paid", "cancelled", "paid", "paid"],
    }
)

working = raw.assign(
    order_date=lambda frame: pd.to_datetime(frame["order_date"])
)
```

`raw` остаётся исходной стадией, `working` получает date dtype.

## Выбирай строки одной boolean mask

```python
july_paid = (
    working["status"].eq("paid")
    & working["order_date"].ge("2026-07-01")
    & working["order_date"].lt("2026-08-01")
)

selected = working.loc[
    july_paid,
    [
        "order_id",
        "order_date",
        "region",
        "units",
        "unit_price",
        "discount_rate",
    ],
].copy()
```

Правая граница записана как `< 2026-08-01`. Такой half-open interval включает
весь июль независимо от времени внутри последнего дня.

Для сочетания условий нужны круглые скобки вокруг отдельных сравнений, если ты
используешь операторы `&` и `|`. Python `and` и `or` не выполняют
поэлементное сравнение Series.

<Callout kind="warning">
  Избегай `working[mask]["column"] = value`. Chained selection затрудняет
  понимание, изменился ли исходный DataFrame. Выбирай через `.loc[...]` и явно
  создавай `.copy()` для новой стадии.
</Callout>

## Рассчитывай показатели именованными стадиями

```python
selected = selected.assign(
    gross_revenue=lambda frame: frame["units"] * frame["unit_price"],
)

selected = selected.assign(
    net_revenue=lambda frame: (
        frame["gross_revenue"] * (1 - frame["discount_rate"])
    ),
    month=lambda frame: frame["order_date"].dt.to_period("M").astype("string"),
)
```

[`DataFrame.assign`](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.assign.html)
возвращает новый DataFrame и позволяет ссылаться на columns, созданные ранее в
цепочке. Разделение gross и net revenue делает скидку наблюдаемой.

Контроли:

```python
assert selected["order_id"].tolist() == ["A-2", "A-3", "A-5"]
assert selected["month"].eq("2026-07").all()
assert selected["net_revenue"].sum() == 4470.0
assert len(raw) == 6
```

Net revenue:

- A-2: `1 × 1200 × 0.9 = 1080`;
- A-3: `3 × 450 = 1350`;
- A-5: `4 × 600 × 0.8 = 1920`.

Сумма равна `4350`, а не `4470`. Этот конфликт — полезная проверка: письменный
контроль и ручной расчёт не согласуются. Исправь assert:

```python
assert selected["net_revenue"].sum() == 4350.0
```

<Callout kind="error">
  Правдоподобный expected value тоже может быть ошибочным. Если assert падает,
  проверь и код, и ожидание по независимому малому примеру; не меняй число
  только ради зелёной проверки.
</Callout>

## Необязательное углубление

<Callout kind="advanced">
  Ту же mask можно выразить через `.query()`, а стадии — одной method chain.
  Используй такой стиль только если names и boundaries остаются читаемыми.
  Сравни две версии по ease проверки, а не по числу строк.
</Callout>
