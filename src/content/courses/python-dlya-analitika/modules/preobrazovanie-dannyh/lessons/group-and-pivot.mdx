Фильтр определяет, какие строки участвуют. GroupBy определяет grain ответа.
Вопрос «какова выручка по месяцу и региону?» означает одну итоговую строку на
комбинацию `month × region`.

## Назови grain до groupby

```python
import pandas as pd

orders = pd.DataFrame(
    {
        "order_id": ["O-1", "O-2", "O-3", "O-4", "O-5", "O-6"],
        "month": ["2026-06", "2026-06", "2026-06", "2026-07", "2026-07", "2026-07"],
        "region": ["north", "north", "south", "north", "south", "south"],
        "net_revenue": [1000.0, 1500.0, 900.0, 1200.0, 1300.0, 1700.0],
    }
)
```

Одна строка исходника — заказ. Итоговая строка — месяц и регион:

```python
summary = (
    orders.groupby(["month", "region"], as_index=False)
    .agg(
        orders=("order_id", "nunique"),
        revenue=("net_revenue", "sum"),
        average_order=("net_revenue", "mean"),
    )
    .sort_values(["month", "region"])
)
```

Named aggregation показывает column и функцию рядом с именем результата.
Официальное руководство называет модель
[`split-apply-combine`](https://pandas.pydata.org/docs/user_guide/groupby.html):
разделить на группы, применить aggregation, объединить результаты.

Проверь:

```python
assert len(summary) == 4
assert summary["revenue"].sum() == orders["net_revenue"].sum()
```

В исходнике 6 заказов, но summary имеет 4 combinations. Сумма выручки до и
после должна совпасть, потому что каждая строка входит ровно в одну группу.

## Функция агрегации следует вопросу

| Вопрос | Aggregation |
| --- | --- |
| Сколько уникальных заказов? | `nunique` по `order_id` |
| Какова общая выручка? | `sum` |
| Каков средний заказ? | `mean` на grain заказа |
| Каково типичное время при выбросах? | возможно `median` |

Среднее средних без учёта размеров групп обычно неверно. Если north имеет 2
заказа, а south — 100, их average orders нельзя усреднить с одинаковым весом
для общего показателя. Возвращайся к исходному grain или сохраняй numerator и
denominator.

## Pivot меняет форму, не смысл

```python
revenue_pivot = summary.pivot(
    index="month",
    columns="region",
    values="revenue",
)
```

Строки — месяцы, columns — регионы, cells — revenue. Pivot удобна для сравнения
и будущего графика, но она не должна выполнять скрытую aggregation. Поэтому
сначала создаётся summary с уникальным grain, затем вызывается `pivot`.

Проверка по NumPy-модели:

```python
assert revenue_pivot.shape == (2, 2)
assert revenue_pivot.to_numpy().sum() == orders["net_revenue"].sum()
```

## Необязательное углубление

<Callout kind="advanced">
  `pd.crosstab()` быстро строит counts по двум категориям, а `pivot_table()`
  совмещает aggregation и reshape. Сравни их с явным `groupby().agg()` +
  `pivot()`. Для core analysis оставляй тот вариант, где grain и aggregation
  легче проверить.
</Callout>
