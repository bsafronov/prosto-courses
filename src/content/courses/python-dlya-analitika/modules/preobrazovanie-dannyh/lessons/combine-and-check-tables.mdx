`merge` может выполниться без ошибки и удвоить выручку. Причина — не синтаксис,
а неверное ожидание о ключах. До объединения назови grain обеих таблиц и
ожидаемую cardinality.

## Many-to-one: много заказов, один товар

```python
import pandas as pd

orders = pd.DataFrame(
    {
        "order_id": ["O1", "O2", "O3", "O4"],
        "product_id": ["P1", "P2", "P2", "P3"],
        "revenue": [1000.0, 1200.0, 800.0, 1500.0],
    }
)

products = pd.DataFrame(
    {
        "product_id": ["P1", "P2", "P3"],
        "category": ["basic", "standard", "premium"],
    }
)
```

Grain:

- `orders`: одна строка — заказ;
- `products`: одна строка — товар;
- ожидание: много orders соответствуют одному product.

До merge:

```python
assert orders["order_id"].is_unique
assert products["product_id"].is_unique
rows_before = len(orders)
revenue_before = orders["revenue"].sum()
```

Объединение:

```python
combined = orders.merge(
    products,
    on="product_id",
    how="left",
    validate="many_to_one",
    indicator=True,
)
```

`validate="many_to_one"` заставит pandas проверить ожидаемую cardinality.
`indicator=True` добавляет `_merge` со значениями `both`, `left_only` и
`right_only`.

После merge:

```python
assert len(combined) == rows_before
assert combined["revenue"].sum() == revenue_before
assert combined["_merge"].eq("both").all()
```

Документация
[`pandas.merge`](https://pandas.pydata.org/docs/reference/api/pandas.merge.html)
описывает типы join, validation и indicator. Для аналитика критичны не все
параметры, а три evidence: cardinality, row count и unmatched keys.

<Callout kind="key">
  Safe merge начинается с проверки уникальности lookup key и заканчивается
  сравнением row count, totals и `_merge`.
</Callout>

## Как many-to-many размножает строки

Представь ошибочный справочник:

```python
bad_products = pd.DataFrame(
    {
        "product_id": ["P1", "P2", "P2", "P3"],
        "category": ["basic", "standard", "standard-copy", "premium"],
    }
)
```

Два заказа P2 совпадут с двумя строками lookup: вместо двух строк появятся
четыре. Merge без `validate` создаст 6 строк и завысит revenue.

## Unmatched keys — отдельный результат

```python
unmatched = combined.loc[
    combined["_merge"].eq("left_only"),
    ["order_id", "product_id"],
]
```

Left join сохраняет заказы без справочника и позволяет измерить gap. Inner join
молча удалил бы их, если не сравнить число строк.

## Необязательное углубление: Polars и DuckDB

<Callout kind="advanced">
  pandas остаётся core tool для in-memory notebook и богатой работы с
  DataFrame. [Polars](https://docs.pola.rs/user-guide/) предлагает expression
  API, lazy execution и Arrow-oriented engine.
  [DuckDB](https://duckdb.org/docs/stable/) выполняет SQL прямо по локальным
  CSV/Parquet и удобен, когда вопрос естественно выражается запросом.

  Не меняй инструмент из-за моды. Сравни: объём и format данных, знакомый язык
  команды, необходимость lazy plan/SQL, memory limit и способ проверки
  результата. Grain, keys, cardinality и reconciliation нужны во всех трёх
  инструментах.
</Callout>
