Один dataset допускает десятки графиков. Выбор сокращается, если сначала
назвать relationship, который должен увидеть читатель.

| Аналитический вопрос | Структура данных | Базовый chart |
| --- | --- | --- |
| Какая категория больше? | category + measure | bar |
| Как показатель меняется во времени? | ordered time + measure | line |
| Как распределены отдельные наблюдения? | one numeric variable | histogram или boxplot |
| Связаны ли два числовых показателя? | x + y на grain наблюдения | scatter |

Chart type не доказывает причинность и не исправляет aggregation. Сначала нужна
evidence table на правильном grain.

## Начни с готовой таблицы

```python
import pandas as pd

summary = pd.DataFrame(
    {
        "month": ["2026-06", "2026-06", "2026-07", "2026-07"],
        "channel": ["chat", "email", "chat", "email"],
        "tickets": [120, 80, 140, 95],
        "median_hours": [4.0, 12.0, 5.0, 14.0],
    }
)

assert not summary.duplicated(["month", "channel"]).any()
```

Grain — `month × channel`. Возможны разные вопросы:

- «Как изменилась median resolution time по каналам?» → line;
- «Как каналы сравниваются в июле?» → grouped bar или две простые bars;
- «Как распределено время отдельных tickets?» → эта summary не подходит:
  отдельные наблюдения уже потеряны.

<Callout kind="warning">
  Нельзя построить честный histogram из четырёх групповых median и назвать его
  распределением tickets. После aggregation исходное distribution недоступно.
</Callout>

## Bar показывает category comparison

```python
import matplotlib.pyplot as plt
import seaborn as sns

july = summary.loc[summary["month"].eq("2026-07")].copy()

fig, ax = plt.subplots(figsize=(7, 4))
sns.barplot(
    data=july,
    x="channel",
    y="median_hours",
    errorbar=None,
    ax=ax,
)
ax.set(
    title="Медианное время решения обращений в июле",
    xlabel="Канал",
    ylabel="Медианное время, часы",
)
fig.tight_layout()
```

Мы передаём уже aggregated table и отключаем statistical error bars.
Seaborn умеет агрегировать raw data автоматически, но скрытая aggregation
затрудняет проверку. В core analysis summary создаётся отдельно.

## Line показывает ordered change

```python
trend = summary.sort_values(["channel", "month"])

fig, ax = plt.subplots(figsize=(7, 4))
sns.lineplot(
    data=trend,
    x="month",
    y="median_hours",
    hue="channel",
    style="channel",
    markers=True,
    dashes=False,
    ax=ax,
)
ax.set(
    title="Медианное время решения обращений по месяцам",
    xlabel="Месяц",
    ylabel="Медианное время, часы",
)
fig.tight_layout()
```

`style` и markers добавляют различие кроме цвета. Две точки на series ещё не
показывают устойчивый trend; chart только сравнивает June и July.

[`Matplotlib quick start`](https://matplotlib.org/stable/users/explain/quick_start.html)
объясняет Figure/Axes model, а
[`Seaborn tutorial`](https://seaborn.pydata.org/tutorial.html) — high-level
statistical plotting API.

## Необязательное углубление: Plotly

<Callout kind="advanced">
  Plotly добавляет hover, zoom и interactive selection. Это полезно для
  exploration и web-sharing, но interaction не исправляет неверный grain и
  создаёт дополнительные требования к export/accessibility. Сравни
  [Plotly Express](https://plotly.com/python/plotly-express/) с текущим static
  chart по задаче читателя. Не добавляй dependency в core project без
  конкретной потребности.
</Callout>
