Есть минимально достаточная спецификация. Нужно ли теперь поместить её в один
идеальный prompt, попросить ассистента задавать вопросы или разбить работу на
шаги?

Режим выбирают не по длине текста и не по моде. Смотри на неизвестность,
зависимость действий, потребность в инструментах и возможность проверить
промежуточный результат.

## Выбери самый простой режим, который удерживает риск

| Режим | Наблюдаемые признаки задачи | Главная граница |
| --- | --- | --- |
| Один запрос | Цель и исходные данные известны; действие компактно; результат можно сразу проверить | Не сжимай сюда неизвестные требования только ради краткости |
| Уточняющий диалог | Существенные условия неизвестны и человек может их прояснить | Диалог должен завершиться консолидированной спецификацией, иначе ранние догадки накапливаются |
| Многошаговый workflow | Есть зависимые подзадачи, разные инструменты или проверяемые промежуточные артефакты | Дополнительный шаг оправдан, только если он проще и оставляет проверяемый след |

Декомпозиция помогает некоторым сложным задачам, но не является универсальным
законом: каждый лишний шаг создаёт новую точку ошибки
([Least-to-Most Prompting](https://arxiv.org/abs/2205.10625),
[ReAct](https://arxiv.org/abs/2210.03629)). Поэтому «workflow» не означает
«нарезать ответ на много сообщений». У каждого шага должны быть вход,
проверяемый артефакт и условие продолжения.

### Один кейс — три режима

Задача запуска курса меняется в трёх версиях:

1. **Известный формат.** По утверждённым датам преобразовать список этапов в
   таблицу. Один запрос достаточен: исходные данные полны, проверка формата и дат
   непосредственна.
2. **Неизвестная цель пилота.** Владелец ещё не решил, проверяет ли пилот
   завершение, применение навыка или операционный результат. Нужен
   уточняющий диалог о требованиях: без ответа критерии и план будут догадкой.
3. **План с источниками и бюджетом.** Сначала извлечь ограничения, затем
   проверить расчёт, затем собрать план, затем сверить утверждения и риски. Нужен
   workflow, потому что ошибки раннего шага должны остановить продолжение.

Уточняющий диалог не равен бесконечной переписке. После ответов собери единую
версию спецификации и попроси владельца подтвердить её перед выполнением.
Workflow тоже может включать диалог, если один из шагов обнаруживает
существенную неизвестность.

  подтвердит владелец. Для workflow опиши минимум три шага с артефактом,

  большое число элементов ещё не требует сложного workflow; возможна пакетная
  обработка с общей проверкой. Затем выбери режим для собственной задачи и
  запиши два признака, которые заставят его изменить.
