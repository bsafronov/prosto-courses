Одна и та же спецификация может быть оформлена заголовками Markdown,
XML-подобными блоками или JSON. Ни один вариант не делает содержание истинным.
Формат решает более узкую задачу: показывает границы частей человеку, модели
или следующей программе.

Официальные руководства Anthropic и Google рекомендуют явную структуру и
разделители для текущих моделей. Исследования чувствительности запросов показывают,
что даже смыслово близкие варианты оформления способны менять результат, а
удачный формат плохо переносится между моделями
([Anthropic, Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices),
[Google, Prompt design strategies](https://ai.google.dev/gemini-api/docs/prompting-strategies),
[Sclar et al., 2023](https://arxiv.org/abs/2310.11324)). Поэтому структура —
проверяемый выбор, а не тайная команда.

## Выбирай по функции

| Форма | Основная функция | Подходящий следующий потребитель | Чего не гарантирует |
| --- | --- | --- | --- |
| Markdown | Читаемые заголовки, списки, таблицы и блоки | Человек или совместное редактирование | Что модель учтёт каждую секцию |
| XML-подобные блоки | Явные именованные границы инструкции, данных и примеров | Модель и человек, которым важны вложенные части | Истинность, безопасность или защиту от внедрения инструкций через недоверенные данные |
| JSON | Стабильные поля и типы для машинного чтения | Программа или автоматическая следующая стадия | Фактическую правильность значений |

Markdown-вариант:

```md
## Задача
Сравни два варианта пилота.

## Данные
- максимум 15 участников;
- дата старта неизвестна.

## Результат
Таблица вариантов и список открытых решений.
```

XML-подобный вариант:

```xml
<instruction>Сравни два варианта пилота.</instruction>
<data trust="owner-confirmed">
  Максимум 15 участников. Дата старта неизвестна.
</data>
<output>Таблица вариантов и список открытых решений.</output>
```

JSON-вариант результата:

```json
{
  "recommendedOption": "pilot-a",
  "participantLimit": 15,
  "startDate": null,
  "openDecisions": ["startDate", "successCriterion"]
}
```

JSON синтаксически аккуратен, но поле `participantLimit` всё равно может
содержать выдуманное `50`. Специальные режимы структурированного результата некоторых API
могут ограничивать результат поддерживаемой JSON Schema, однако схема проверяет
форму, а не соответствие значения источнику; у режимов есть документированные
исключения ([OpenAI, Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs),
[Anthropic, Structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs),
[Google, Structured output](https://ai.google.dev/gemini-api/docs/structured-output)).

<Callout kind="warning">
  XML-подобный блок отделяет недоверенный текст визуально, но не повышает его
  приоритет и не защищает систему сам по себе. Граница доверия задаётся
  инструкциями системы и проверками.
</Callout>

Guidance, а не блокировка: для этого Lesson достаточно читать готовые секции и

  Изменённый случай: результат передаётся человеку через обычное письмо, без
  автоматической обработки. Объясни, почему JSON здесь создаёт лишнюю стоимость.
  Затем выбери форму для следующего потребителя собственной задачи.
