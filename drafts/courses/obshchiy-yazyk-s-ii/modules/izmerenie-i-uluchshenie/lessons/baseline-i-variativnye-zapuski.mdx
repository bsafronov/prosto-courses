После первого неудачного ответа хочется сразу дописать: «будь точнее». Но
исправленный prompt уже нельзя честно сравнить с исходным, если команда не
сохранила вход, условия запуска и результаты. Один плохой ответ тоже не
показывает, повторяется ли ошибка и на каких случаях.

**Baseline** — исходные результаты до содержательного изменения. Это не один
выбранный скриншот и не среднее впечатление. Это версия prompt, набор случаев,
условия запуска, результаты и профиль по рубрике.

## Зафиксируй сравнение до правки

Минимальная карточка baseline:

| Поле | Что записать |
| --- | --- |
| Версия | Полный prompt и идентификатор версии |
| Система | Видимое название модели или продукта, дата, доступные инструменты |
| Настройки | Существенные параметры, если интерфейс их показывает |
| Вход | Полные данные каждого проверочного случая |
| Повторы | Заранее выбранное число запусков по каждому случаю |
| Результаты | Каждый результат без отбора только удачных |
| Проверка | Свидетельства по каждому измерению рубрики |
| Ограничение вывода | Что этот малый набор не проверяет |

Граница модели, ассистента и инструмента снова важна. Новый результат мог
появиться не из-за prompt, а после смены модели, включения поиска или изменения
системных инструкций продукта. Если условие изменилось и его нельзя вернуть,
зафиксируй новый baseline вместо ложного сравнения.

## Распределяй повторы по риску и вариативности

Один обычный случай может дать устойчивый результат, а провокационный — три
разных. Поэтому сначала назначь небольшой прозрачный протокол, затем расширяй
его по наблюдениям:

| Случай | Первый протокол | Когда расширить |
| --- | --- | --- |
| Полные данные типичного пилота | Два запуска | Свойство рубрики расходится между запусками |
| Неизвестная дата | Три запуска | Хотя бы один результат превращает неизвестное в факт |
| Неподтверждённое обещание эффекта | Три запуска | Ошибка появляется хотя бы раз или меняет решение |
| Точный бюджетный предел | Один результат плюс независимый пересчёт | Меняются исходные данные или расчёт |

Числа не являются универсальной статистической нормой. Они показывают
решение команды: больше повторов там, где генеративная вариативность способна
скрыть дорогую ошибку; точный расчёт проверяется независимо. OpenAI рекомендует
вести журнал результатов, использовать оценки под задачу и включать в набор
входы, похожие на рабочее распределение
([Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)).

Baseline команды дал:

| Случай | Наблюдения |
| --- | --- |
| Обычный, два запуска | Оба ответа соблюли лимиты и назвали следующий шаг |
| Неизвестная дата, три запуска | В двух дата сохранена как открытая; в одном объявлена подтверждённой |
| Обещание эффекта, три запуска | В двух обещание повторено без источника; в одном удалено |
| Бюджетный предел, один запуск | Текст назвал сумму допустимой; независимый расчёт подтвердил ровно 240 000 ₽ |

Вывод локален: в этих восьми результатах ошибки концентрируются на статусе даты и
неподтверждённом эффекте. Нельзя говорить «prompt ошибается в 37,5 процента
случаев вообще»: набор мал и специально содержит рискованные входы. Но можно
выбрать измеренное отклонение для следующей гипотезы.

<Callout kind="key">
  Baseline нужен не для красивой метрики. Он сохраняет точку сравнения,
  вариативность и границы вывода до того, как ты увидишь новую версию.
</Callout>

## Сними baseline без выбора любимого ответа

  подсчёт слов. Затем запиши карточку baseline для собственной задачи.

Baseline превращает впечатление в наблюдение. Следующий урок использует
измеренное отклонение, формулирует одну гипотезу и сохраняет причинную цепочку
в журнале итераций.
